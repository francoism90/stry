# S3 Object Storage

## Introduction

**stry** stores these in S3-compatible object storage:

- 🖼️ **Conversions** - Thumbnails and image transformations
- 🎬 **Segments** - DASH/HLS video chunks for streaming
- 🔐 **Secrets** - DASH/HLS encryption keys

:::note
Any AWS and Laravel compatible S3 service that supports signed URLs will work (AWS S3, MinIO, RustFS, Garage, etc.).
:::

---

## Prerequisites

**Required:**

- A compatible S3 service

## Usage

[RustFS](https://github.com/rustfs/rustfs) is used in this guide.

**Step 1:** Make sure RustFS is running:

```bash
systemctl --user start stry-rustfs
systemctl --user status stry-rustfs
```

In the `development` preset, the RustFS web console is accessible directly at [http://localhost:9001](http://localhost:9001). The `frankenphp-octane` (production) preset doesn't expose it by default — add it to the `CaddySites::render()` map in `config/octane.php` if you want it reachable through the app's [Reverse Proxy](proxy.md).

**Step 2:** Run the setup command:

:::tip
If you're not already inside the container, enter the shell first:

```bash
lpod stry shell
```

:::

```bash
php artisan podman:s3-setup
```

The command reads its credentials from the `s3` disk in `config/filesystems.php`, which in turn reads `.env` (`AWS_ENDPOINT`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`). These must match the credentials configured in your S3 service.

It creates the required buckets (`podman.s3_buckets`) and applies the CORS policy from the published `s3` runtime (`podman.s3_cors_buckets`). Both are configurable via `php artisan vendor:publish --tag=podman-config`.

### RustFS credential variables

RustFS and AWS environment variable names map as follows:

- `RUSTFS_ACCESS_KEY` -> `AWS_ACCESS_KEY_ID`
- `RUSTFS_SECRET_KEY` -> `AWS_SECRET_ACCESS_KEY`

RustFS reads these from the `stry-rustfs-access-key`/`stry-rustfs-secret-key` Podman secrets (see `rustfs.quadlets`), set via:

```bash
lpod stry-rustfs secrets
```

:::info
In production, always use strong, randomly generated credentials for `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`. Never reuse development credentials. Generate a secure secret key with:

```bash
openssl rand -hex 16
```

Update your `.env` file with the new credentials before running the setup script.
:::

:::note
All buckets are **private by default**. `podman:s3-setup` only creates buckets and applies the CORS policy — it does not set any public bucket policy. Signed URLs embed AWS SigV4 credentials in the URL itself, so they authenticate the request without requiring public bucket access.
:::

## CORS

Browsers enforce CORS even on signed URL requests — a bucket must respond with `Access-Control-Allow-Origin` headers or the request gets blocked. `podman:s3-setup` applies the CORS policy from the `s3` preset's `cors.json` automatically (`containers/stubs/s3/cors.json` once published, otherwise the vendor default).

To verify:

```bash
aws s3api get-bucket-cors --bucket segments
```
