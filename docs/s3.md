# S3 Object Storage

## Introduction

S3-compatible object storage is used by **stry** for storing:

- 🖼️ **Conversions** - Thumbnails and image transformations
- 🎬 **Segments** - DASH/HLS video chunks for streaming
- 🔐 **Secrets** - DASH/HLS encryption keys

> [!NOTE]
> Any AWS and Laravel compatible S3 service that supports signed URLs will work (AWS S3, MinIO, RustFS, Garage, etc.).

---

## Prerequisites

**Required:**

- A compatible S3 service

---

## Usage

[RustFS](https://github.com/rustfs/rustfs) is used in this guide.

**Step 1:** Make sure RustFS is running:

```bash
systemctl --user start stry-rustfs
systemctl --user status stry-rustfs
```

The RustFS web console is accessible at [https://fs.stry.test](https://fs.stry.test).

**Step 2:** Run the setup command:

> [!TIP]
> If you're not already inside the container, enter the shell first:
>
> ```bash
> stry shell
> ```

```bash
php artisan podman:s3-setup
```

The command uses the credentials already configured on the `s3` disk in `config/filesystems.php`, which read from your `.env` file (`AWS_ENDPOINT`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`) — the same values must match the credentials configured in your S3 service.

This will create all required buckets (`podman.s3_buckets`) and apply the CORS policy from the published `s3` runtime (`podman.s3_cors_buckets`). Both are configurable via `php artisan vendor:publish --tag=podman-config`.

### RustFS credential variables

RustFS and AWS environment variable names map as follows:

- `RUSTFS_ACCESS_KEY` -> `AWS_ACCESS_KEY_ID`
- `RUSTFS_SECRET_KEY` -> `AWS_SECRET_ACCESS_KEY`

For local Podman setups, the RustFS credentials live in
`containers/podman/systemd/stry/config/rustfs.env`.

> [!NOTE]
> If a variable is defined multiple times in an env file, the last value wins.
> In the current RustFS env file, example placeholder values are defined first,
> and active local-development credentials are defined later.

> [!IMPORTANT]
> In production, always use strong, randomly generated credentials for `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`. Never reuse development credentials. Generate a secure secret key with:
>
> ```bash
> openssl rand -hex 16
> ```
>
> Update your `.env` file with the new credentials before running the setup script.

> [!NOTE]
> All buckets are **private by default**. Signed URLs embed AWS SigV4 credentials in the URL itself, so they authenticate the request without requiring public bucket access. The `assets` bucket allows anonymous `GetObject` access so fonts and icons can be served directly.

---

## CORS

Browsers enforce CORS even on signed URL requests — buckets must respond with `Access-Control-Allow-Origin` headers or the request will be blocked. The CORS policy in `containers/runtimes/policies/cors.json` is applied automatically by `setup-s3`.

To verify:

```bash
aws s3api get-bucket-cors --bucket segments
```
