# S3 Object Storage

## Introduction

S3-compatible object storage is used by **stry** for storing:

- 🖼️ **Assets** - Fonts and icons
- 🖼️ **Conversions** - Thumbnails and image transformations
- 🎬 **Segments** - DASH/HLS video chunks for streaming
- 🔐 **Secrets** - DASH/HLS encryption keys

> [!NOTE]
> Any AWS and Laravel compatible S3 service that supports signed URLs will work (AWS S3, MinIO, RustFS, Garage, etc.).

---

## Prerequisites

**Required:**

- A compatible S3 service
- AWS CLI (provided by the container)

---

## Usage

[RustFS](https://github.com/rustfs/rustfs) is used in this guide.

**Step 1:** Make sure RustFS is running:

```bash
systemctl --user start stry-rustfs
systemctl --user status stry-rustfs
```

The RustFS web console is accessible at [https://fs.stry.test](https://fs.stry.test).

**Step 2:** Run the setup script:

```bash
./bin/setup-s3.sh
```

The script reads credentials from your `.env` file automatically. If you prefer to pass them directly, you can export them beforehand — the values must match the credentials configured in your S3 service:

```bash
export AWS_ENDPOINT_URL=http://systemd-stry-rustfs:9000
export AWS_ACCESS_KEY_ID=<your-access-key>
export AWS_SECRET_ACCESS_KEY=<your-secret-key>
```

This will create all required buckets and apply the CORS and bucket policies.

> [!IMPORTANT]
> In production, always use strong, randomly generated credentials for `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`. Never reuse development credentials. Generate a secure secret key with:
>
> ```bash
> openssl rand -hex 32
> ```
>
> Update your `.env` file with the new credentials before running the setup script.

> [!NOTE]
> All buckets are **private by default**. Signed URLs embed AWS SigV4 credentials in the URL itself, so they authenticate the request without requiring public bucket access. The `assets` bucket allows anonymous `GetObject` access so fonts and icons can be served directly.

---

## CORS

Browsers enforce CORS even on signed URL requests — buckets must respond with `Access-Control-Allow-Origin` headers or the request will be blocked. The CORS policy in `containers/runtimes/policies/cors.json` is applied automatically by `setup-s3.sh`.

To verify:

```bash
aws s3api get-bucket-cors --bucket segments
```
